# Implementation decisions against the frozen spec (v1)

`docs/FABLE_SESSION_1_SPEC.md` stays frozen. These are the places where it was internally inconsistent or silent, and what the code does instead. Each was made while acting on GPT's review of `114589a` (`MarketLab_Quant_Guild_Review.md`). The next Fable audit should check them.

| # | Spec | Problem | Implementation (branch `integrity-replay`) |
| --- | --- | --- | --- |
| E1 | §4.1 target includes slippage; §5.2, §5.3 and §4.5 subtract s_in + s_out again | Slippage was counted twice | Labels are gross: actual opens, listed-action factors, minus the benchmark. Slippage and charges are subtracted once, by the allocator before the trade and by the ledger at the fills. This matches §2.5 ("only gross quantities are modelled, costs are subtracted by the allocator"). The §5 worked numbers are unchanged. The §2.4 example becomes: 100 → 104 gives gross 4.0000% (log 0.039221); with the index 23,000 → 23,230 (log 0.009950) the excess is 0.029271 in log terms. |
| E2 | §5.2 gate 4: "there exists q (within caps)" | The gate was checked at the largest position, but a smaller whole-share quantity could fail it | Every planned position is rechecked at its chosen quantity with exact rupee-rounded charges and DP. Review case: ₹2,100 a share, μ̃ 0.86%, slippage 0.20%. The ₹5,000 gate passes (threshold 0.8293%), but 2 shares (₹4,200) have a net edge of 0.0821%, below 0.10%, so no trade. |
| E3 | §2.2 entry is a pre-open market order | A market order's cash need is unknown when the decision is made, so the next open could change the quantity | EXEC.v1 places a pre-open limit buy at C_D × 1.05 and blocks funds at that limit. If O(1+s_in) is above the limit the order is REJECTED_GAP. The spec's deferral rule is unchanged: no trade means FILL_DEFERRED, and more than 3 deferrals means ENTRY_FAILED. A missing data session means CANCELLED_DATA_GAP. A session locked at the upper band (H = L > base price) counts as no trade. |
| E4 | Silent on when sale proceeds become usable | — | Proceeds are counted in NAV at once. They can fund an order decided after the next session (T+1), or after two sessions before 27 Jan 2023 (T+2, conservative across the phase-in). This is stricter than broker same-day credit and is unverified. |
| E5 | §2.4: exclude windows with unlisted factors | The default code path multiplied every factor it found | Windows with an unlisted factor are excluded (UNEXPLAINED_PRICE_ADJUSTMENT), and so are windows crossing an unchecked day (ACTION_COVERAGE_UNKNOWN). The ledger still applies the factor to units held and flags the position FACTOR_UNVERIFIED or FACTOR_LISTED. |
| E6 | §3.1 rule 1: "ETF" in the name or on the ETF list | The code also matched GOLD, SILVER and LIQUID, which excludes ordinary companies, and it used the latest name for every date | An ISIN with the INF prefix is excluded, as is a name containing ETF, BEES or EXCHANGE TRADED, using the name printed on that day. |
| E7 | §3.1: "the after-close files ... available before the decision" | The screen read the decision session's own rules, one session stale | The screen uses the rule files of the entry session (the next session). The replay uses reconstructed availability (spec §2.1, labelled). Forward decisions use only files received before the decision. |
| E8 | §8.6 lists criteria but not how to compute them | — | Only verified folds count: calendar sessions, rule files present, no data gaps, no flagged corporate action. N_eff uses the within-date residual ICC of the test forecasts over h-session entry blocks. DSR uses n = N_eff and the registered trials' Sharpe variance. PBO is CSCV with 16 blocks on the mean daily NAV return, because Sharpe is undefined for a trial that never trades. MinTRL is symmetric: for SR < 0 it is the record needed to establish the loss, so a conclusive loser is REJECT, not INSUFFICIENT EVIDENCE. Concentration fails when net ≤ 0. Following the review, attribution (beta and alpha of daily NAV) must exist. Missing evidence gives INSUFFICIENT EVIDENCE. |
| E9 | §8.3: the inner fold chooses λ and supplies the conformal residuals | The same observations do both (review) | Unchanged. Coverage is validated on the walk-forward test folds, which are fresh chronological blocks, and it gates promotion (the review's alternative). |
| E10 | §8.4 Brier skill "vs climatology" | The code used the test fold's own base rate | The reference is the training base rate, which is usable at decision time. The test-rate version is reported as a diagnostic. The pinball reference uses training quantiles. |
| E11 | §8.1: the holdout is "the last 12 months before the backfill date" | The code used "the last 250 stored sessions", which moved as data grew | `marketlab freeze-holdout` writes `runs/holdout.json` once and the date never moves. Development runs read a panel view ending the day before it. |
| E12 | §5.5 triggers | — | Triggers are BELOW_ENTRY_Q10 and the screen's rule exclusions (surveillance, suspension, call auction, series, band). A held stock with no forecast at a required review is EXIT. |
| E13 | Silent on holdings at a fold boundary | They were valued at entry | They are valued at liquidation at the fold's last close (exit slippage, exact sell charges, DP). A blocked exit carries bounds [0, liquidation]. Folds are independent: each starts at the policy capital. |
| E14 | §6 criterion 5 stresses | — | Costs ×2, slippage ×2 and entry one session late act on execution only: decisions keep the base cost model. "Best 5% removed" drops the top ceil(5%) of closed trades. |
| E16 | §2.4 says `PrvsClsgPric` on an ex-date is the exchange-adjusted base price, so the implied factor f_X gives the action ratio | **False in the 2025 UDiFF files (historical pilot).** The base price equals the previous unadjusted close on split and bonus ex-dates (IGL, SHRIRAMFIN), and splits often issue a new ISIN under the same symbol (30 cases in 7 months). The implied-factor method found 1 factor in 146 sessions. | `Panel.compute_discontinuities` records one-session jumps outside [0.795, 1.255] and ISIN successions. A label crossing either is excluded (`PRICE_DISCONTINUITY_UNEXPLAINED`, `IDENTITY_CHANGE`), and so is a feature window containing a jump. The ledger flags held positions. Genuine crashes in unbanded stocks are excluded too (bias risk) until an official action history supplies ratios. H-CA1 (dividends): no adjustment in the one case observed (INFY, 30 May 2025). |
| E15 | §5.3 ρ from 60-session returns | Silent when fewer days are common | With fewer than 20 common return days, ρ = 0.3 (the §0 assumption). |
| E17 | §3.3 features "from adjusted prices"; §2.4 adjustment | No adjustment existed: a listed split or bonus inside a 251-session window removed the stock's features for a year (E16 detection) | With the corporate-action registry (NSE API 2016–2026, hash-verified; every split/bonus ratio checked against the jump), a RATIO_CONSISTENT action corrects that day's return (ln(close / (base × f)) when the base was not adjusted) and restates earlier prices for the 250-session range and breadth. A new ISIN that began on a listed action's ex-date inherits its predecessor's bars. Unlisted jumps and unexplained ISIN changes are unchanged (missing data). Without a registry the computation is identical (tested). Live and replay share it through `evaluate.build_dataset`. |
| E18 | Silent on presenting a per-stock view before promotion | Only a WAIT decision with diagnostics existed | RANK.v1 (`quant/ranking.py`) uses the decision's own code (`decide.fit_today`) and labels every stock: buy candidate, qualifies, hold off, high risk, avoid, not eligible or no forecast (rules in docs/STOCK_RANKING.md). AVOID mirrors the buy threshold: shrunk μ ≤ −(cost + minimum edge), or an exchange risk flag. A tail-gate failure is HIGH_RISK, not AVOID. Rankings are research output: write-once files that never create paper orders, and forward evidence only when created before the entry session opens. |
| E19 | §4.4 shrinkage μ̃ = μ̂·τ²/(τ²+se²) with se from the bootstrap of the whole prediction | **Owner decision 2026-11-06.** The intercept and market features are the same for every stock on a date, so they form a market-timing forecast estimated from only ~15 independent 20-session periods (311 training dates). On 5 Nov 2026 their bootstrap se was 1.30% against 0.47% for the stock-specific part; one total se cut the stock signal to 12% (shrink 0.116 instead of 0.526). Measured out of sample on the purged calibration window (8 Jul–6 Oct 2026, 50,324 rows): stock-specific IC +0.13, positive on 63 of 63 dates, top-minus-bottom decile +3.06% per 20 sessions; only 4 non-overlapping periods, so this is a lead, not proof. | `forecast.predict` shrinks the two parts separately: μ̃ = shrink(common, se_common) + shrink(specific, se_specific), same τ. Cards carry `mu_common`, `mu_specific`, `se_common`, `se_specific`. |
| E20 | §5.2 gate 5: q10 − cost ≥ −L for the position | **Owner decision 2026-11-06.** L is the account's loss limit; applied to a single position's return it rejected 783 of 801 stocks (a typical stock's 10% month is about −15%) and became stricter as positions shrink with diversification. | Gate 5 is (position ÷ capital) × (q10 − cost) ≥ −L (`allocate.capital_tail_loss`). At ₹10,000 the largest position is half the capital, so a −15% month costs the account −7.5%. L stays 8%. The q10 is still of excess return over the Nifty 50, not total return: a known limitation. |
| E21 | §3.1 universe: EQ only, median traded value ≥ ₹5 crore, one share ≤ half the capital | **Owner decision 2026-11-06: analyse every stock.** | `service.screen_policy`: EQ and BE series (BE is trade-for-trade, fine for delivery); no liquidity floor by default (owner policy `v_min_crore` default 0); no price rule. Illiquidity is costed, not excluded: per-side slippage 0.10% ≥ ₹10 cr, 0.25% ≥ ₹5 cr, 0.50% ≥ ₹1 cr, 1.00% ≥ ₹25 lakh, 2.00% below (`labels.ILLIQUID_TIERS`, an assumption until a measured spread estimator replaces it) and flagged `LOW_LIQUIDITY`. A share above the per-stock cap is forecast and labelled `ONE_SHARE_ABOVE_POSITION_CAP` (hold off) at that capital. ETFs, SME (SM/ST), BZ, surveillance, suspension and bands < 10% stay screened. Rankings record the screen they used. |
| E22 | §5.2 gate 5 and EXIT.v1 "below entry q10" use the forecast's q10 | **Owner review 2026-11-07 (external critique, confirmed).** The forecast and its conformal range are of the EXCESS return over the Nifty 50, but the tail gate and the exit trigger are about money lost: a stock lagging the index by 12% loses about 7% in a +5% market and about 17% in a −5% one. The exit compared the lot's absolute simple return with the excess log q10. | `forecast.fit` also calibrates the stock's ABSOLUTE log return (`z_abs_sorted`: residuals of the own return, the index centred on its calibration-window mean, so no market drift is assumed) and `predict` gives `q10_abs/q50_abs/q90_abs`. The tail gate, its threshold and the EXIT.v1 trigger use `replay.downside_q10` (absolute when calibrated) and compare log with log. The edge gate and "beats the index" keep the excess forecast. The range chart shows both rows on one % axis, and the tail line is the gate solved for q10: cost − L·W/position (e.g. −21.43% for ₹3,588 of ₹10,000, not cost − L). |
| E23 | E19's stock-specific shrinkage from the block bootstrap alone | **Owner review 2026-11-07.** The bootstrap measures only in-sample variation over ~15 blocks: on 5 Nov BALAMINES' stock part had se 0.22% on a 1.78% signal (t ≈ 8), which is overconfident about regime change. | The stock-specific factor is min(τ²/(τ²+se²), clip(slope, 0, 1)), where `slope` is the pooled within-date regression slope of realized excess on the stock-specific forecast over the purged calibration window: the stock signal is never believed more than it held up out of sample. Cards and explanations state both factors and reconcile raw = common + specific and μ̃ = f_c·common + f_s·specific; μ̃ can exceed μ̂ when an uncertain negative market part offsets a reliable positive stock part, and the page says so. |
